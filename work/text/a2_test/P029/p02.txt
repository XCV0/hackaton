2 Preliminary and Motivation
2.1 Why We Need a Real-World RAG Trace
with Temporal Information?
Existing generic LLM-Specific traces are funda-
mentally inadequate for RAG serving systems.
This limitation arises from the distinctive workload
characteristics of RAG, which diverge substantially
from standalone LLM inference and thus require
dedicated, RAG-specific traces.
First, RAG introduces an inherent multi-stage
execution pipeline. Each request traverses mul-
tiple tightly coupled phases—including retrieval,
re-ranking, and generation (Yu et al., 2025; Asai
et al., 2024; Lu et al., 2024). End-to-end latency, re-
source utilization, and cache behavior are therefore
governed by cross-stage interactions rather than by
generation alone. Generic LLM traces, which pri-
marily capture the prefilling and decoding phase,
fail to expose these composite system effects.
Second, RAG performance is highly depen-
dent on both the underlying knowledge base and
real-world query patterns (Yue et al., 2025; He
et al., 2024; Gutiérrez et al., 2024). Workload
dynamics such as query similarity and document
cache hit rates vary significantly with user behav-
ior. Moreover, practical deployments often exhibit
strong inter-request correlations, where consecu-
tive queries share overlapping contexts or retrieved
documents. Accurately capturing these temporal
and content-level dependencies is essential for op-
timizing scheduling, batching, and KV cache reuse
policies (Agarwal et al., 2025; Jin et al., 2024).
Third, most existing RAG traces are derived
from synthetic or curated chat workloads, which
typically contain limited document corpora and
lack authentic temporal locality information. Op-
timizations validated on non-representative traces
often fail to generalize to production environments,
resulting in performance gaps and unstable system
behavior. This disconnect substantially hinders the
practical advancement of RAG serving systems.
Beyond characterization, RAG-specific traces
are critical for enabling joint optimization of re-
trieval and generation. Treating these components
as independent black boxes limits the design space
of RAG serving systems. In contrast, realistic RAG
traces make it possible to co-optimize retrieval
caching, query-adaptive batching, and scheduling
decisions across pipeline stages (Wang et al., 2024).
Taken together, these limitations underscore the
need for a real-world, production-grade RAG trace
to ground system design and evaluation in realistic
workload behaviors.
