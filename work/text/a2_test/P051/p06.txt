4. Tool Support
We provide RAG-TESTER as an Open-Source end-to-
end RAG-LLM test generation tool that enables testing
Retrieval Augmented Language Models via a user-friendly
web interface or a code-based environment. Both interfaces
provide parity in core functionalities: PDF generation, test
generation, test execution and test evaluation.
Whilethecode-basedversionallowsfordirectexecution
anddebugging,thewebinterfaceoffersamoreappealingtest
resultvisualization,makingiteasiertoidentifystrengthsand
weaknesses.Furthermore,RAG-TESTER isengineeredwith
a modular architecture, so if developers wish to implement
new LLM providers, document loaders, etc. the process
remains simple and extensible. A demo for the tool using
the web interface can be found online [20].
5. Experimental Design
5.1. Research Questions
Our evaluation aimed at answering the following four
Research Questions (RQs):
• RQ1–Overallperformance:HowdoesRAG-TESTER
performatdetectingfailuresonRAG-enabledLLMs?
With this RQ we wanted to assess the overall per-
formance provided by RAG-TESTER when testing
different LLM and embedding combinations.
• RQ2 – Comparison with Baseline: How does RAG-
TESTERcomparewithabaselinetestinputgenerator?
InthisRQweaimedatcomparingRAG-TESTERwith
a simplified version of the test input generator we
developed.
• RQ3 – PDF Generation Strategies: Which is the
difference between generating the context PDF files
automatically or employing existing PDF files? In
the third RQ we aimed at answering whether there
are differences in generating the context files in an
automated manner.
• RQ4–OraclePrecision:Whichistheprecisionofthe
test oracles of RAG-TESTER? Since RAG-TESTER’s
oracle employs an LLM-as-a-judge, it might have
certain proneness to hallucination. This RQ aims at
checking its precision to investigate whether and to
which extent the proposed test oracle triggers false
positives.
