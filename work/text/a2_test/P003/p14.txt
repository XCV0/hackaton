Parallelization and comparison with conven-
tional RAG. URGen follows the same high-
level dependency structure as conventional RAG:
ﬁrst select relevant information, then answer the
question conditioned on the selected information.
The difference is that URGen evaluates multi-
ple ranking temperatures and multiple answer-
generation temperatures. These branches are in-
dependent after model loading. Therefore, when
sufﬁcient GPU resources or batching capacity are
available, the critical path is still one keypoint-
ranking batch followed by one answer-generation
batch, similar to the retriever-then-reader structure
of conventional RAG. In other words, URGen in-
creases total batched computation, but it does not
introduce a long sequential reasoning chain.
This property gives URGen a practical advan-
tage over iterative adaptive methods such as RQ-
RAG (Chan et al., 2024). RQ-RAG reﬁnes or de-
composes the query into multiple retrieval queries
before answer generation, so later retrieval steps
can depend on preceding generated queries. Such
query-reﬁnement pipelines are harder to fully par-
allelize and can accumulate errors when interme-
diate rewritten queries drift from the clinical in-
tent of the input question. URGen instead keeps
the input medical question ﬁxed and estimates re-
trieval ambiguity through multi-temperature key-
point ranking. This makes the adaptive step sim-
ple, parallelizable, and directly tied to the uncer-
tainty of the keypoint distribution.
