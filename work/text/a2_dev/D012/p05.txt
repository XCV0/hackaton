Pre-Generation Governance Router. Before re-
trieved evidence is placed in the generation prompt,
the Governance Router applies deterministic meta-
data filtering. For each candidate document di, it
evaluates both access permission and explicit su-
persession status. The admissible document set
is:
Dallowed = {di ∈ D | can_access(di, r) = 1
∧ idi /∈ S(D)}.
Documents that fail either condition are recorded in
Ddropped together with their rejection reasons, such
as access_denied or superseded. The filtered
evidence context is constructed only from Dallowed:
C(q, r, D) = concat({ci | di ∈ Dallowed}).
If Dallowed = ∅, TrustRAG does not invoke the
LLM and instead returns a deterministic refusal
with the routing evidence. This prevents the gen-
erator from producing an answer from an empty
admissible context.
Conflict-Reporting Generation. When
Dallowed ̸= ∅, TrustRAG prompts the LLM
with the filtered evidence context C(q, r, D) and
conflict-reporting rules. The prompt requires the
model to generate the response only from the
filtered evidence context. If multiple accessible
and non-superseded documents contain incom-
patible facts and no explicit supersession relation
resolves the conflict, the response should enter the
CONFLICTREPORT state by reporting the conflict
and the distinct values in the retained evidence,
rather than forcing a single answer. In the current
implementation, conflict handling is enforced
through a model-agnostic prompting policy.
3.3 Routing-Level Invariants and Scope
Given correct and complete governance metadata
for the retrieved candidate set, TrustRAG enforces
the following routing-level invariants before gen-
eration:
• Access invariant: If can_access(di, r) = 0,
then its content ci is excluded from C(q, r, D).
This prevents context-induced use of access-
denied evidence.
• Supersession invariant: If idi ∈ S(D), then
ci is excluded from C(q, r, D). This prevents
context-induced use of explicitly superseded
evidence.
• Empty-context invariant: If Dallowed = ∅,
TrustRAG returns REFUSAL instead of invok-
ing the LLM without admissible context.
• Conflict-preservation invariant: If accessi-
ble and non-superseded documents contain
an unresolved conflict, TrustRAG preserves
the retained evidence for CONFLICTREPORT
rather than resolving the conflict by timestamp
order.
These invariants are scoped to the retrieved can-
didate document set and the provided metadata.
Specifically, the access invariant requires correct
document access labels and user-role mappings,
whereas the supersession invariant requires stable
document identifiers, correct and complete super-
