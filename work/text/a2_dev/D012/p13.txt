A.2 Prompt and Output Specifications
We provide the prompt templates for TrustRAG,
Prompt RAG, the LLM-based baselines, and the
governance-aware judge. Placeholders in angle
brackets are replaced with the corresponding in-
stance fields. All generator models use the same
method-specific templates and a sampling tempera-
ture of 0.1.
Input format. Metadata-aware methods receive
each candidate document as:
METADATA: {"doc_id": "<DOC ID>",
"access_level": "<ACCESS LEVEL>",
"date": "<DATE>", "supersedes":
"<SUPERSEDED DOC ID>"}
CONTENT: <DOCUMENT CONTENT>
The supersedes field is omitted when no explicit
relation is specified. Routed prompts additionally
receive the user role, retained document identifiers,
filtered context, and question.
Prompt RAG and TrustRAG. Prompt RAG re-
ceives all retrieved documents without physical
filtering:
System: You are a metadata-aware
aerospace QA assistant. You receive all
retrieved documents, including
metadata, but no document has been
physically filtered. For the stated
user clearance, do not reveal
access-denied facts. Treat documents
named in a supersedes field as inactive.
If active accessible documents conflict
and no supersedes edge resolves the
conflict, report the conflict rather
than choosing one value.
User:
USER CLEARANCE: <USER ROLE>
RETRIEVED CONTEXT:
<SERIALIZED CANDIDATE DOCUMENTS>
QUESTION: <QUESTION>
Answer according to the metadata
governance rules.
After deterministic access and supersession rout-
ing, TrustRAG uses:
System: You are an aerospace compliance
QA assistant. Answer only from the
FILTERED ACTIVE CONTEXT. Do not use,
mention, or reconstruct removed
documents. If multiple active documents
conflict and no explicit supersedes
metadata is present, state that the
active sources conflict and report both
active values.
User:
USER CLEARANCE: <USER ROLE>
ALLOWED_DOC_IDS: <ALLOWED DOCUMENT IDS>
FILTERED ACTIVE CONTEXT:
<FILTERED ACTIVE CONTEXT>
QUESTION: <QUESTION>
Return a concise answer grounded only
in the filtered active context.
