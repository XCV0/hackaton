# Как устроен проект CyberGarden

## Одна запись от начала до конца

Мы делаем сервис, который читает научные статьи в PDF и переносит их результаты в связанные таблицы. У каждой цифры есть адрес в статье. На защите можно найти цифру, открыть страницу, посмотреть условия эксперимента и понять, почему программа ей доверяет или отправила на проверку.

Реальный пример есть в RAG-публикации **D004**, в таблице 3 на странице 6. Авторы проверили, насколько мнения в найденных документах похожи на мнения во всей коллекции. Для варианта **Raw KB** получилось **8,87**, для **Enriched KB** — **7,24**. Они использовали одну и ту же метрику **Wasserstein distance (W1)**, сравнили варианты на одном корпусе **Forums**, взяли по 20 найденных документов и в статье указали, что у W1 меньшее число лучше.

| Вопрос | Что хранит наша программа |
|---|---|
| Из какой статьи число? | `publication_id = D004` |
| Какая система показала результат? | `config_id = C2`, обогащённая база |
| На каких данных? | `dataset_id = DS1`, корпус Forums |
| Что и как проверяли? | `task_id = T1`, вопросы о мнениях. `experiment_id = E1`, общий порядок сравнения |
| Что получилось? | `metric_name = Wasserstein distance`, исходное значение `7.24` |
| Где это видно? | Страница 6, таблица 3, строка `Forums 8.87 7.24 −18%` |
| Кто получил число? | `primary`. Измерение провели авторы этой статьи |

По аналогии в Solar-публикации **D004**, на странице **12**, записано, что напряжение холостого хода выросло с **0,8 В до 1,05 В**. В примере число 1,05 относится к конкретному прибору и измерению. Старый фрагмент заканчивался на 0,8 В. Я расширил цитату до 1,05 В в исходном PDF. Идентификатор D004 повторяется в двух наборах, поэтому внутри сервиса учитывается ещё и область.

```text
Научная статья → найти значение → записать условия → проверить источник → поиск и выгрузка
                    7,24              Forums, k=20         D004, стр. 6
```

## Откуда взялся RAG

Представь школьную библиотеку. Ты задаёшь вопрос, библиотекарь находит нужные страницы, а ученик читает их и отвечает своими словами. **RAG (Retrieval-Augmented Generation)** работает в таком порядке. Компонент поиска приносит источники, модель использует их при составлении ответа. По этой технологии написана одна группа статей. Наш сервис собирает из них настройки и результаты экспериментов. В собственном интерфейсе у нас полнотекстовый поиск по уже извлечённым записям.

| Термин | Что он значит |
|---|---|
| **Запрос, query** | Вопрос или строка, по которой система ищет документы. |
| **Корпус, коллекция, KB** | Документы, из которых можно брать сведения. KB означает базу знаний. |
| **Датасет, dataset** | Набор для исследования. Например, вопросы с эталонными ответами и документами. Название, версия и разбиение помогают понять, на каких примерах мерили. |
| **Benchmark** | Датасет вместе со способом оценки, по которому можно сверять работы. |
| **Split, train/dev/test** | Части данных. На train учатся. На dev настраивают и проверяют в разработке. На test оценивают на отложенных примерах. |
| **QA, single-hop, multi-hop** | QA — ответы на вопросы. Для single-hop хватает одного факта. Для multi-hop нужно связать несколько фактов. |
| **Retriever, retrieval** | Модуль поиска и сам этап поиска. На выходе — отобранные документы или куски текста. |
| **BM25, sparse retrieval** | Поиск по словам. BM25 учитывает совпадения, редкость слова и размер документа. |
| **Embedding, dense retrieval** | Embedding — набор чисел, которым модель описывает смысл текста. Dense retrieval сравнивает такие наборы чисел. Может связать разные формулировки одного смысла. |
| **Hybrid retrieval** | Совмещает поиск по словам и поиск по смыслу. |
| **Chunk, chunking, overlap** | Чанк — кусок документа. Chunking нарезает его на куски. Overlap повторяет конец одного куска в начале следующего, чтобы сохранить мысль на границе. |
| **Token** | Единица текста для модели. Одно слово может состоять из нескольких токенов. |
| **Index, vector store, FAISS** | Индекс ускоряет поиск. Хранилище векторов сохраняет числовые представления и связанные данные. FAISS — библиотека для поиска похожих векторов. |
| **Top-k, reranking** | Top-k ограничивает число кандидатов. Reranker перечитывает первые результаты и меняет их порядок. |
| **Generator, LLM** | Модель, которая пишет ответ. LLM означает «большая языковая модель». |
| **Prompt, zero-shot, context** | Prompt — инструкция модели. Zero-shot — инструкция без демонстрационных примеров. Context — сведения, которые модель видит в текущем запросе. |
| **Конфигурация, variant, ablation** | Конфигурация — набор деталей и настроек. Variant — один вариант системы. Ablation — проверка вклада детали, которую отключают или заменяют. |
| **Baseline, oracle** | Baseline — опорный способ для сравнения. Oracle в эксперименте получает идеальную подсказку, чтобы оценить верхнюю границу. |
| **Протокол** | Правила эксперимента. Они задают, какие вопросы взяли, что посчитали правильным и как свели результаты. |
| **Grounding, галлюцинация** | Grounding — опора ответа на найденные сведения. Галлюцинация — уверенно написанное утверждение без подтверждения. |

У статей есть своё чанкование для их RAG. Наш конвейер тоже делит загружаемую статью на куски для модели. `chunk_size` в строке данных относится к системе авторов статьи.

### Метрики из RAG-статей

| Термин | Объяснение на пальцах |
|---|---|
| **Metric, variant, direction, scale** | Что считаем, какой именно вариант, в какую сторону лучше и в каких пределах может быть значение. У точности больше обычно лучше, у задержки меньше. |
| **Exact Match, EM** | Доля ответов, полностью совпавших с правильным после приведения формата, если это предусмотрено протоколом. |
| **Accuracy, Acc** | Доля правильных решений по правилам конкретной задачи. |
| **Precision@k** | Какая доля первых k результатов подходит. Если из пяти подходят три, это 3/5. |
| **Recall@k** | Какую долю всех подходящих результатов нашли среди первых k. Если подходящих всего 10, а нашли 3, это 3/10. |
| **Hit@k** | Есть ли среди первых k хотя бы одно попадание. На наборе вопросов можно посчитать долю запросов с попаданием. |
| **MRR** | Смотрим место первого полезного ответа. Первое даёт 1, второе — 1/2, третье — 1/3. Потом берём среднее. |
| **nDCG@k** | Даёт больше баллов за хорошие документы наверху. Сверяет порядок с идеальным ранжированием. |
| **MAP** | Усредняет качество выдачи по позициям, где встретились подходящие документы, а затем по запросам. |
| **F1 ответа** | Может учитывать совпавшие слова или токены. Нужно читать определение в статье. |
| **BLEU, ROUGE, BERTScore** | Способы сопоставить сгенерированный текст с эталоном. BLEU и ROUGE опираются на совпадения в тексте, BERTScore использует представления токенов. Шкалу берём из статьи. |
| **Wasserstein distance, W1** | Насколько две картины распределения отличаются. В D004 это мнения среди найденных документов и мнения во всей коллекции. |
| **Latency, sample size, aggregation** | Задержка ответа, число примеров и способ их свести. Агрегацией могут быть среднее, медиана, micro или macro. |

**Нюанс для жюри.** `top_k = 20` значит «поиск достаёт 20 документов». `metric_k = 5` значит «показатель считает первые пять». Оба числа могут использоваться в одном эксперименте.

## Как читать солнечную часть

Солнечный элемент превращает часть света в электричество. Тонкоплёночный элемент состоит из нескольких тонких слоёв. У каждого слоя своя работа. Кейс ограничен изготовленными однопереходными приборами и их экспериментами.

| Термин | Что он значит |
|---|---|
| **Перовскит, CIGS, CdTe, кестерит, Sb₂Se₃, тонкоплёночный Si** | Семейства материалов или поглотителей света. Например, CIGS — соединение меди, индия, галлия и селена. |
| **Однопереходный и тандем** | В однопереходном приборе каждый фотоэлемент содержит один фотоактивный переход. Тандем совмещает несколько переходов, которые используют разные части спектра. |
| **Substrate, superstrate** | Подложка держит слои. В superstrate-конфигурации свет входит со стороны прозрачной подложки. |
| **Поглотитель, ETL, HTL, контакт** | Поглотитель принимает свет, ETL переносит электроны, HTL переносит дырки, контакт выводит ток. |
| **n-i-p, p-i-n** | Порядок слоёв: n связан с электронами, p с дырками, i обозначает активную область между ними. |
| **Deposition, annealing, encapsulation** | Нанесение слоя, обработка нагревом и защитная упаковка прибора. |
| **Control, target, champion** | Контрольный образец для отсчёта, основной исследуемый образец и лучший из измеренных. Среднее по партии храним отдельной записью. |
| **Активная площадь, маска** | Область, участвующая в измерении. Маска задаёт, какая часть светится, поэтому важна для сравнения плотности тока. |
| **J–V, ВАХ, sweep** | Зависимость тока от напряжения. Sweep — проход по напряжениям. Прямой и обратный проходы могут дать разные цифры. |
| **AM1.5G, Pin** | Эталонное солнечное освещение и мощность падающего света на единицу площади. Для основного сравнения в ТЗ указано 100 мВт/см². |
| **Voc, В** | Напряжение на разомкнутых контактах, когда ток наружу не течёт. |
| **Jsc, мА/см²** | Ток короткого замыкания, поделённый на площадь. |
| **FF, fill factor** | Коэффициент заполнения. Показывает, насколько мощность в лучшей рабочей точке близка к произведению Voc и Jsc. |
| **PCE, КПД** | Доля мощности света, которую прибор отдаёт как полезное электричество. |
| **MPP** | Точка максимальной мощности. Слежение за ней помогает измерять рабочий КПД во времени. |
| **EQE, Jsc_EQE** | EQE показывает, сколько зарядов получили на падающий фотон при разных длинах волн. По EQE можно отдельно оценить Jsc. |
| **Eg, eV, Eg/q** | Ширина запрещённой зоны, обычно в электрон-вольтах. Eg/q — соответствующая шкала напряжения. Система проверяет, что Voc ниже этого значения. |
| **Rs, Rsh, HI** | Последовательное сопротивление, сопротивление утечке и индекс различия между направлениями развёртки. |
| **T80, ISOS, стабильность** | T80 — время до снижения до 80% от исходного показателя. ISOS задаёт условия испытания, например свет, нагрев или хранение. |
| **Сертификация** | Независимая проверка измерения. Это отдельное условие сравнения. |

**Пример расчёта с условными числами.** Пусть Voc = 1 В, Jsc = 25 мА/см², FF = 80%, Pin = 100 мВт/см². Сначала берём FF как долю 0,8. Выходная мощность на единицу площади получается 1 × 25 × 0,8 = 20 мВт/см². Делим 20 на 100 и получаем КПД 20%. Если статья пишет 22% с теми же условиями, сервис сохраняет 22% и создаёт замечание по формуле. Отдельные числа могли относиться к разным приборам, поэтому карточка с источником нужна для проверки человеком.

## Что делает код с PDF

| Этап или термин | Что происходит |
|---|---|
| **Регистрация, инвентаризация** | Учитываем файл, имя, число страниц, наличие текста и статус. DOI — постоянный идентификатор публикации, SHA-256 — цифровой отпечаток файла для поиска одинаковых копий. |
| **Парсинг, текстовый слой** | PDF хранит размещение текста на странице. Парсер достаёт символы и пытается восстановить порядок чтения. |
| **Скан, OCR** | В скане страница может быть просто картинкой. OCR превращает пиксели в текст. Он может перепутать 0 и O, потерять минус или смешать колонки. |
| **Vision** | Чтение изображения и его структуры. Понадобится, чтобы сопоставить подпись, кривую и значение на графике. Распознанный текст и прочитанная глазами кривая — разные виды доказательств. |
| **Сегментация** | Делим статью по разделам и страницам. Промпт содержит маркеры страниц, чтобы модель могла указать источник. |
| **Схема, сущность, поле, ID** | Схема описывает колонки и типы. Сущность — вид объекта, например эксперимент. Поле — одна его характеристика. ID связывает строки разных таблиц. |
| **Raw, normalized** | Raw — как записали авторы. Normalized — как храним для сравнения после обоснованного пересчёта. Например, 841 мВ и 0,841 В. |
| **Provenance, source_fragment** | Происхождение. Храним статью, физический номер страницы PDF, при наличии раздел, таблицу или рисунок и дословную цитату. |
| **Primary, cited** | Primary — число получили авторы этой работы. Cited — число взято из чужой статьи. Воспроизведённый авторами baseline может быть primary. |
| **Duplicate, duplicate_of** | Повтор результата в другом месте той же статьи хранится с привязкой к основной строке. Для экспериментов с разными условиями создаются отдельные записи. |
| **Нормализация, словарь** | Приводим единицы и варианты названий к общему виду. Пустое поле означает, что сведений нет. Ноль — измеренное нулевое значение. |
| **Верификация цитаты** | Код ищет цитату на странице и отдельно проверяет число. Совпадение строки ещё не доказывает правильный выбор колонки. |
| **Предметная валидация, issue** | Правило проверяет формулу, диапазон, единицу или связь. Issue хранит найденную проблему, причину и связанные строки. |
| **Статусы** | `extracted` — извлекли. `present_not_extractable` — статья упоминает результат, число достоверно недоступно. `verified` — запись прошла применённые проверки. `flagged` — требует внимания. `rejected` — исключена из публичной выдачи, остаётся в БД. |
| **Уровень важности, аудит** | Ошибка, предупреждение или информационное замечание. Аудит хранит, кто и когда отредактировал или подтвердил данные. |
| **Кворум, нода, каскад** | Нода — отдельный прогон извлечения. Кворум — согласие нескольких прогонов по тому же значению и контексту. Каскад вызывает дополнительные проверки на спорных строках. Это идея из памятки, реализованный конвейер выбирает одного провайдера на прогон. |

### Что работает под капотом

- **Frontend** — страницы, кнопки и карточки в браузере. **Backend** читает PDF, обращается к модели, считает правила и отдаёт данные.
- **FastAPI** — Python-библиотека для маршрутов сервера. **Uvicorn** — процесс, который принимает запросы браузера и передаёт их приложению.
- **SQLite** — локальная база в одном файле. **FTS5** — полнотекстовый индекс в SQLite. Поиск по обработанным данным идёт через него и обходится без запроса к LLM.
- **API** — договор, куда и какие данные отправлять. **Base URL** — адрес сервиса. **API-ключ** — пароль для запросов. **Провайдер** — сервис, который запускает модель. **Ollama** запускает модель на своём компьютере. **Воркер** обрабатывает одну работу из очереди.
- **CSV** — текстовая таблица, **JSON** — данные с именованными полями и вложенностью, **ZIP** — архив нескольких таблиц. **Паспорт** объясняет колонки, допустимые значения и связи.
- **Git** хранит историю проекта. **Коммит** записывает набор изменений. **Main** — основная ветка GitHub.

## Как сказать о качестве честно

**Gold, эталон** — независимая разметка для сравнения. Сначала извлекаем результаты, затем сравниваем их с эталоном. Если взять числа прямо из эталона и потом сравнить с ним, оценка покажет копирование.

Допустим, в эталоне 10 нужных записей. Наш сервис вернул 8 строк, из них 6 верных.

| Показатель | Что считаем | Пример |
|---|---|---|
| TP | Верные совпадения | 6 |
| FP | Лишние или ошибочные строки | 2 |
| FN | Пропущенные эталонные строки | 4 |
| Precision | Доля верных среди найденного | 6/8 = 75% |
| Recall | Доля найденных среди эталона | 6/10 = 60% |
| F1 | Баланс двух долей | 2 × 6 / (12 + 2 + 4) ≈ 66,7% |
| Покрытие | Сколько статей вообще обработали | Например, 3 из 21 |

Встроенная оценка проекта считает precision, recall и F1 по заполненным полям сопоставленных записей. Поэтому score зависит от правил matching — по каким полям считаются одинаковыми две строки. Микроусреднение складывает совпадения и ошибки по полям, затем считает меры. Макроусреднение сначала считает меру по каждому поднабору и даёт этим поднаборам одинаковый вес.

## Вопросы, которые может задать жюри

| Вопрос | Короткий ответ |
|---|---|
| Зачем два набора таблиц? | У солнечного прибора есть слои и измерения, у RAG — настройки поиска и датасеты. Чтение PDF, проверки, поиск и экспорт общие. |
| Что если интернет пропал? | Обработанные данные, поиск, исходные PDF, подсветка и выгрузки доступны из локальной базы. Новому PDF для извлечения нужна рабочая модель, облачная либо локальная. |
| Почему не показать просто ответ модели? | Нам важны область, условия, исправления и источник каждого числа. Ответ модели проходит эти проверки перед публикацией. |
| Как поймёте, что цифра принадлежит нужной системе? | Сохраняем идентификаторы, страницу, строку таблицы и описание столбца. Человек сверяет сложные таблицы и рисунки. |
